# Installation

Solar UI is built on top of **shadcn/ui** and **Tailwind CSS**. Components are distributed via the shadcn registry, which means you install only what you need — directly into your codebase.

<Steps>

### Create a Next.js project

If you don't have a project yet, scaffold one with:

```bash filename="terminal" copy
npx create-next-app@latest my-project --typescript --tailwind --eslint --app --src-dir --import-alias "@/*" --yes
cd my-project
```

<Callout type="info">
  npm does not allow uppercase letters in package names. Use lowercase (e.g. `my-project`, not `MyProject`).
</Callout>

### Initialize shadcn/ui

Solar UI requires shadcn/ui as a foundation. If your project doesn't have it yet, run:

```bash filename="terminal" copy
npx shadcn@latest init --defaults
```

This generates `components.json` and sets up the base configuration for your project.

### Configure the Solar UI registry

Tell shadcn where to resolve Solar UI components by adding a `registries` entry to your `components.json`:

```json filename="components.json" copy
{
  "registries": {
    "@solar-ui": {
      "url": "https://solar-ui.com/r/{name}.json"
    }
  }
}
```

<Callout type="info">
  Without this configuration, shadcn won't know how to resolve `@solar-ui/*` component identifiers and will fail with a "not found" error.
</Callout>

### Add the Solar UI theme

Install the Solar UI theme, which applies the design tokens and visual style across your components:

```bash filename="terminal" copy
npx shadcn@latest add https://www.solar-ui.com/r/solar-ui.json
```

This creates the token files in `src/app/`, mirroring the three Figma variable collections:

| File | Figma collection | Contents |
| --- | --- | --- |
| `radix.css` | Mode | Radix Colors primitives, light and dark |
| `screen.css` | Screen | Sizes and type scales, desktop and mobile |
| `themes/stellar.css`, `themes/trevia.css` | Theme | Semantic tokens, one file per theme |
| `theme.css` | — | Entry point: imports the above and exposes them to Tailwind |

### Import the theme in globals.css

Open `src/app/globals.css` and import `theme.css` right after Tailwind. It pulls in the other files itself:

```css filename="src/app/globals.css" copy
@import "tailwindcss";
@import "./theme.css";
```

### Choose a theme

The default theme is the one written as a `@theme` block. That single block both declares the token names to Tailwind — without `--color-brand-9`, the class `bg-brand-9` does not exist — and supplies the default values. Other themes only carry a `data-theme` rule.

```css filename="src/app/themes/stellar.css"
@theme {                        /* ← makes this the default theme */
  --color-brand-9: var(--orange-9);
}
```

```css filename="src/app/themes/trevia.css"
:root[data-theme="trevia"] {    /* applies only when selected */
  --color-brand-9: var(--blue-9);
}
```

Tailwind writes `@theme` into `@layer theme`, and an unlayered rule always beats a layered one whatever its specificity — so a `data-theme` rule reliably overrides the default.

Import order is irrelevant: Turbopack reorders `@import` between dev and build, so relying on it would give you a different default in each mode. To promote another theme, move the `@theme` wrapper into its file and turn the current default back into a `:root[data-theme="stellar"]` rule.

Every imported theme stays reachable at runtime — set `data-theme` on `<html>` to switch, and combine it freely with the `dark` class:

```html
<html data-theme="trevia" class="dark">
```

### Override a token

Theme defaults are declared with `:where(:root)`, which has zero specificity. A plain `:root` rule in your own stylesheet overrides any of them, no `!important` needed:

```css filename="src/app/globals.css" copy
:root {
  --color-brand-9: var(--violet-9);
}
```

### Add your first component

You can now install any Solar UI component. Since shadcn/ui already generates a default `button.tsx`, use the `-f` flag to override it with the Solar UI version:

```bash filename="terminal" copy
npx shadcn@latest add @solar-ui/button -y -o
```

The `-y` flag skips the confirmation prompt and `-o` forces the override of the existing file. Repeat this pattern for any other component you want to add.

### Use the component

Import and use the component like any other React component:

```tsx filename="src/app/page.tsx" copy
import { Button } from '@/components/ui/button'

export default function Page() {
  return <Button>Click me</Button>
}
```

All Solar UI components live in `src/components/ui/` and are fully editable — they're part of your codebase, not a black-box dependency.

</Steps>
